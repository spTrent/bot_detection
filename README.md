# Детекция ботов-парсеров по событиям куки

Для каждой `cookie_id` модель выдаёт `score` от 0 до 1: вероятность того, что кука принадлежит известному сервису автоматического сбора данных. Метрика: Precision при Recall >= 0.7 (`src/metric.py`).

## Структура

| файл | что внутри |
|---|---|
| `notebooks/eda.ipynb` | EDA: окна, воронка, время, User-Agent, контент, курсор, рейтинг признаков |
| `notebooks/model.ipynb` | разбиение train/test, бейзлайн на правилах, логистическая регрессия, CatBoost, итоговая метрика на test |
| `src/features.py` | построение всех признаков по куке (`build_features`) |
| `src/models.py` | создание и подбор гиперпараметров всех моделей |
| `src/metric.py` | метрика P@R >= 0.7 с учётом одинаковых скоров |
| `src/inference.py` | загрузка сохранённой модели и скоринг новых кук, команда `score-cookies` |
| `models/` | CatBoost, обученный на train (`catboost.joblib`), и подобранные параметры всех моделей (`best_params.json`), сохраняются из `model.ipynb` |

## Данные

Данные не входят в репозиторий. Для запуска нужно положить в `data/` три файла (модель обучается и проверяется на размеченных куках из `train.csv`, `test.csv` используется в EDA, и его можно оценить обученной моделью через `score-cookies`):

| файл | колонки |
|---|---|
| `train.csv` | `cookie_id`, `cookie_created_at`, `window_start_ts`, `window_end_ts`, `target` (1 бот, 0 человек) |
| `test.csv` | те же колонки без `target` |
| `events.csv.gz` | `cookie_id`, `event_ts`, `eid`, `event_name`, `platform`, `user_agent`, `item_id`, `item_category`, `item_location`, `seller_type`, `search_query`, `search_page`, `pointer_x`, `pointer_y` |

Одна строка `train` и `test` это кука и её суточное окно наблюдения. События это действия на сайте объявлений: просмотр выдачи и объявления, листание фото, страница продавца, контакты, избранное, логин, показ капчи.

## Запуск

Python 3.14.5, зависимости зафиксированы в `pyproject.toml` и `uv.lock`:

```bash
uv sync
```

Команда ставит и группу `dev` (ruff, mypy, pre-commit); только зависимости для запуска ноутбуков: `uv sync --no-dev`.

Модули из `src` ставятся в окружение как пакет, поэтому ноутбуки импортируют их напрямую (`from models import ...`). Затем выполнить `notebooks/model.ipynb` сверху вниз. Везде зафиксирован `random_state=42` (и `seed=42` у сэмплера Optuna), число проб Optuna фиксировано, поэтому результат воспроизводится. Полный прогон с подбором гиперпараметров занимает около часа.

### Сохранённые модель и параметры

В конце `model.ipynb` сохраняются:

- `models/catboost.joblib`: итоговый CatBoost вместе с подготовкой категорий, на вход принимает признаки из `build_features` как есть;
- `models/best_params.json`: лучшие параметры правил, логистической регрессии и CatBoost из Optuna. По ним модель переобучается без повторного подбора: `fit_catboost(load_params('models/best_params.json')['catboost'], features, target)`.

### Скоринг новых кук

Нужны файл с окнами кук в формате `train.csv` (без `target`) и файл событий в формате `events.csv.gz`:

```bash
uv run score-cookies --cookies data/test.csv --events data/events.csv.gz --output scores.csv
```

Результат это csv с колонками `cookie_id` и `score`. Путь к модели меняется флагом `--model`, по умолчанию `models/catboost.joblib`. Из Python то же самое делают `load_model` и `predict_bot_scores` из `src/inference.py`.

## Схема проверки

- **Разбиение по времени.** Размеченные куки из `train.csv` (окна 06.04-19.04) делятся по дате окна: train это окна 06.04-15.04 (8 400 кук, 679 ботов), test это окна 16.04-19.04 (2 691 кука, 220 ботов). Так модель проверяется на днях, которых не видела при обучении.
- **Подбор гиперпараметров только на train:** P@R по out-of-fold предсказаниям `GroupKFold` (5 фолдов, группа это дата окна), чтобы куки одного дня не попадали одновременно в обучение и проверку. Test используется один раз для итоговой оценки каждой модели.

## Обработка событий и окон

- Признаки считаются только по событиям с `window_start_ts <= event_ts < window_end_ts`. Событий до окна в данных нет, события после окна и показы капчи есть только у кук из train и сильно связаны с таргетом (у ботов в 10 раз больше событий после окна), то есть это утечка, и они не используются.
- `platform` записана 11 способами (`WEB`, `Web`, `iphone`, ...) и нормализуется в 4 значения.
- **Пропуски** в признаках осмысленные (у мобильных кук нет курсора, у части кук нет поиска), поэтому на этапе признаков не заполняются: CatBoost работает с NaN сам, для логистической регрессии медиана плюс флаг пропуска.
- **Категориальные признаки** (платформы, вид UA, браузер, ОС, основная категория): OHE в логистической регрессии, нативная поддержка в CatBoost, пропуск в категории становится отдельным значением `missing`.
- **Дубликаты:** 1.5% событий это полные дубли строк. Их доля одинакова у ботов и людей и в train и test, то есть это похоже на артефакт логирования. В текущей версии они не удаляются.

## Признаки

58 признаков по куке, выбраны по результатам EDA (`notebooks/eda.ipynb`, в конце рейтинг каждого признака по отдельности).

| группа | признаки | что нашли в EDA |
|---|---|---|
| интервалы между событиями | медиана, минимум, CV интервалов | самый сильный сигнал: при медиане до 10 с ботов 61%, зависимость U-образная (есть и очень медленные боты) |
| курсор | разброс X и Y, доля точек на краю экрана, доля событий без курсора | у людей курсор равномерно по экрану, у ботов в пятне; при разбросе X до 200 px ботов 66%, есть только у desktop и web |
| глубина выдачи | максимальная страница, доля страниц дальше 3-й, выдач на запрос | с 13-й страницы и дальше ботов 47% |
| разнообразие | разные локации, объявления, категории, запросы | боты смотрят много городов при малом числе категорий |
| воронка | доли типов событий, число логинов | люди чаще листают фото и добавляют в избранное |
| прочее | возраст куки, вид UA, браузер и его версия, энтропия по часам | слабые или средние, оставлены для бустинга |

## Результаты на test (P@R >= 0.7)

| модель | test |
|---|---|
| случайный скор (доля ботов) | 0.082 |
| правила с порогами от Optuna | 0.227 |
| логистическая регрессия | 0.471 |
| **CatBoost, подобранные параметры** | **0.737** |

В test 220 ботов, одна кука меняет метрику примерно на 0.004. Итоговая модель это CatBoost.

## Что пробовали и что не сработало

- **Правила на порогах** плохо подходят к метрике: у большинства кук скор 0, и если на test правила ловят меньше 70% ботов, метрика падает до доли ботов. Подбор с запасом (recall 0.75) частично это исправляет.
- **Логистическая регрессия** не ловит U-образные зависимости и взаимодействия (курсор важен только для desktop и web), бустинг обходит её почти в 1.5 раза.
- **HistGradientBoosting** в предыдущей версии признаков уступал CatBoost (0.713 против 0.741), а ансамбль из двух моделей добавлял около 0.01, поэтому оставлен только CatBoost как более простое решение.
- **Бесполезные гипотезы:** UA автоматизации (75% кук с curl или HeadlessChrome размечены как люди), несогласованность UA и платформы (её нет в данных), ротация UA, события ровно в :00 секунд, пачки событий с одинаковым таймстемпом, число активных часов и самый длинный перерыв в окне, последовательный обход страниц, контакт без предшествующего просмотра объявления, отставание версии браузера от свежих версий (сигнала почти нет, а значение зависело от набора кук, с которым считались признаки, поэтому признак убран; сырая версия браузера осталась).

## Ограничения

- Target это трафик конкретных известных сервисов, а не любая автоматизация: часть явных скраперов размечена как люди, это ограничивает достижимую точность.
- Признаки курсора есть только у трети кук (desktop и web), для мобильных кук модель опирается на время и поведение в выдаче.
- Test маленький (220 ботов), поэтому небольшие различия между моделями на нём ненадёжны.
